**89 份 zip 包裹怎么解的**（这是个坑，纯 `zipfile` 全失败）：
这些文件头是 `PK\x03\x04`，但**没有 central directory**（是流式写入的 zip），`zipfile.ZipFile` 一律抛 `BadZipFile: Bad magic number for central directory`。
正解是**手工扫 local file header**、直接从字节流里找第一个 `.rms` 文件名的末尾，其后全部内容就是平文本脚本：

```python

data = open(path,"rb").read()

i = data.find(b".rms")          # 第一个 .rms 名字的结尾

txt = data[i+4:].decode("utf-8", "replace")

```

89/89 全部还原，且都含完整章节标签，说明这些包的结构就是"`.slp` 二进制在前、`.rms` 明文在后"。
内容含义：这些是**自带自定义地形/装饰贴图**的图，作者把 `.slp` 精灵图和脚本塞进了同一个包里。

## 6 从语料里读出的写法范式

### 6.1 条件分支绝对统治

`elseif` 178604 + `if` 107768 + `endif` 108126 + `else` 31704 = **426202 次**，占全部指令调用的最大宗。
平均每份脚本 629 次条件分支——真实地图是**大量随机分支的堆叠**，不是文档示例那种顺序脚本。
`endif`(108126) ≈ `if`+`elseif`(286372) 说明没有人漏写闭合。

### 6.2 随机块的固定套路

`start_random` 30643 / `percent_chance` 80307 / `end_random` 30654，比例约 1 : 2.6 : 1。
即一个 `start_random` 块平均挂 2.6 个选项——这是"这张图有 N 种变体"的标准写法。
`end_random` 与 `start_random` 数量几乎相等（差 1），说明闭合纪律很好。

### 6.3 地形生成的参数簇

`create_land` 143733 / `land_position` 106584 / `land_percent` 73047 / `base_size` 77856 / `border_fuzziness` 14011。
四个边框指令合计 60119 次（`left_border`+`top_border`+`right_border`+`bottom_border`）。
`create_player_lands`(6421) 仅占 `create_land` 的 4.5%——**绝大多数图用通用 `create_land` + 手动指定玩家位置，而不是引擎自动分配玩家地**。

### 6.4 物件摆放的"防重叠三件套"

`number_of_objects` 138461 / `min_distance_to_players` 98066 / `min_distance_group_placement` 74867 / `max_distance_to_players` 69214，
再加 `set_place_for_every_player` 63485、`group_placement_radius` 50952、`set_tight_grouping` 49003 / `set_loose_grouping` 18511、`set_avoid_player_start_areas` 25614。
这套是"保证金矿不重叠、不贴玩家基地"的实战配方。Zetnus 文档讲得抽象，这里能看到真实用法。
注意 `set_gaia_object_only` 103712 次——说明**绝大多数物件摆放是给中立资源用的**，不是给玩家单位的。

### 6.5 RMS 里直接改游戏数据

`effect_amount` 13473 次出现在脚本里——这是 RMS 内调效果系统的入口，等价于 XS 的 `xsEffectAmount`，
可以在**地图加载时**改单位属性（例："这张图箭塔射程 +2"）。配套 `#const` 定义属性/资源 ID（见 [07 卷](07-XS-ID表-属性资源任务与伤害计算.md) 的 ID 表）。

## 8 怎么用这份语料

1. **查某条指令真实怎么用**：第 5 节搜指令名看"真实写法"；不够就 grep 原文：

   ```bash
   grep -rn "set_place_for_every_player" _probe/_tmp/rms/ | head -20
   ```

2. **抄一张同类图**：先在 `_maps_index.csv` 按标签/版本筛，再打开 `_probe/_tmp/rms/<id>_<slug>.rms`。

3. **判断是不是死语法**：第 5.4 节的 101 条 = 只在 1 张图里出现，属实验性写法。

4. **DE 兼容性检查**：版本只标 `AoC`/`WK`/`UP1.5` 的图，其常量名（`rms_const`，见 [13 卷](13-HALFON-全单位科技数据.md)）在 DE 里可能已改名。

5. **打包自己的图**：把 `.slp` 与 `.rms` 打进一个 zip 就是社区惯例（本卷 89 份样本都是这个结构），游戏能读。
