## 0 一句话结论

awesome-aoe2 的 Programming tools 章节列了 7 个库，真正能今天就用的是 **3 个**：

| 任务 | 唯一可用 | 状态 |
|---|---|---|
| 读写 `empires2_x2_p1.dat`（数据模组） | **genieutils-py 0.1.2** | 完美，字节级无损往返 |
| 读写 `.aoe2scenario`（场景模组） | **AoE2ScenarioParser 0.9.9** | 良好，必须锁 0.9.x |
| 读 `.aoe2record`（录像分析） | **aoe2rec-py 0.1.24** | 能跑，但 4/14 成功率，需容错 |
| 同上（旧版备选） | mgz 1.8.51 | **对 2026 年的录像完全失效** |

`genie-rs` / `genieutils`(C++) / `aoe2rec`(Rust) 三个需要自己编译工具链，本卷不给二进制结论，只标注定位。

## 1 genieutils-py 0.1.2 —— dat 管线的正确答案

### 1.1 装

```bash
pip install genieutils-py
```

国内直连 PyPI 会 `ReadTimeout`，用镜像：

```bash
pip install -U genieutils-py -i https://mirrors.aliyun.com/pypi/simple --timeout 60
```

### 1.2 版本坑（一定要注意）

| 版本 | `Version` 枚举 | VER 8.9 的 dat |
|---|---|---|
| 0.1.1 | 只到 `VER 8.8` | **`ValueError: 'VER 8.9' is not a valid Version`** |
| 0.1.2 | 到 `VER 8.9` | 正常 |

当前 DE（Update 188329 一档）的 dat 头就是 `VER 8.9`。
`Version` 的完整取值：`UNDEFINED, VER 7.1 … VER 7.8, VER 8.4, VER 8.8, VER 8.9`。

枚举定义在 `genieutils/versions.py`，做兼容补丁只需加一行：

```python
s = s.replace("    VER_88 = 'VER 8.8'", "    VER_88 = 'VER 8.8'\n    VER_89 = 'VER 8.9'")
```

（我曾用这份 patch 出来的副本跑通了，但既然 0.1.2 已内置，直接升版即可。）

### 1.3 实测数字

| 操作 | 耗时 |
|---|---|
| `DatFile.parse(11,538,632 B)` | **6.9 s** |
| `d.save(out)` | **4.2 s** |
| 纯往返后再 `parse` | 正常 |

结构规模（这份 dat）：

```
version = VER 8.9
civs    = 63
techs   = 1510
civs[0].units = 2750
```

### 1.4 字节级无损往返（关键验证）

```python
from genieutils.datfile import DatFile

d = DatFile.parse('aoe2mod/tests/out/archer_attack_plus2.dat')
d.save('_probe/_tmp/dattest/rt_same.dat')
```

结果：

```
src 11538632  out 11538632  identical True  diffbytes 0
```

**一个字节都没变。** 这条比任何 README 都重要：说明它可以安全地当"读 → 改一个字段 → 写"的模组管线用，
不会因为重序列化引入隐性差异（对比之下很多 dat 工具重写后体积会变）。

改动后的往返也验证过：

```python
d.techs[22].resource_costs[0].amount = 69     # Loom 金从 50 改 69
d.save('_probe/_tmp/dattest/loom69.dat')
# 重开：tech22 = [(3, 69), (-1, 0), (-1, 0)]
```

### 1.5 对象模型（实测的字段名，不是猜的）

`Unit` 的 `__slots__`（81 个字段，节选关键）：

```
type, id, language_dll_name, language_dll_creation, class_, standing_graphic,
dying_graphic, undead_graphic, undead_mode, hit_points, line_of_sight,
garrison_capacity, collision_size_x/y/z, train_sound, damage_sound,
dead_unit_id, blood_unit_id, sort_number, can_be_built_on, icon_id,

placement_side_terrain, placement_terrain, clearance_size, hill_mode,
fog_visibility, terrain_restriction, fly_mode, resource_capacity,
resource_decay, blast_defense_level, combat_level, interaction_mode,
minimap_mode, interface_kind, multiple_attribute_mode, minimap_color,
language_dll_help, language_dll_hotkey_text, hot_key, recyclable,
enable_auto_gather, create_doppelganger_on_death, resource_gather_group,
occlusion_mode, obstruction_type, obstruction_class, trait, civilization,
nothing, selection_effect, editor_selection_colour,
outline_size_x/y/z, scenario_triggers_1/2, resource_storages,
damage_graphics, selection_sound, dying_sound,
wwise_train_sound_id, wwise_damage_sound_id, wwise_selection_sound_id,
wwise_dying_sound_id, old_attack_reaction, convert_terrain, name, copy_id,
base_id, speed, dead_fish, bird, type_50, projectile, creatable, building
```

**攻击/护甲不在 `Unit` 上，在 `Unit.type_50`（`Type50` 类型）上** —— 这是最容易踩的坑，
`u.attacks` 会直接 `AttributeError`。

`Type50.__slots__`：

```
base_armor, attacks, armours, defense_terrain_bonus, bonus_damage_resistance,
max_range, blast_width, reload_time, projectile_unit_id, accuracy_percent,
break_off_combat, frame_delay, graphic_displacement, blast_attack_level,
min_range, accuracy_dispersion, attack_graphic, displayed_melee_armour,
displayed_attack, displayed_range, displayed_reload_time, blast_damage,
damage_reflection, friendly_fire_damage, interrupt_frame,
garrison_firepower, attack_graphic_2
```

`attacks` / `armours` 是 `[(class_, amount)]` 的列表，`class_` 就是攻击/护甲类别 ID：

```python
u = d.civs[0].units[83]          # VMBAS 村民
u.hit_points                     # 25
[(a.class_, a.amount) for a in u.type_50.attacks]
# [(11, 3), (4, 3), (13, 6), (14, 0), (17, 0), (37, 6)]
[(a.class_, a.amount) for a in u.type_50.armours]
# [(4, 0), (3, 0), (31, 0)]
```

`displayed_*` 系列是"界面显示值"，与真实值分离——做数值 mod 时两者都要改，否则面板显示不动
（本工作区 `stat_displayed_attack_82.dat` 这类文件名就是在处理这件事）。

`Tech.resource_costs` 同样：
`d.techs[22]` = `Loom`，`[(c.type, c.amount)]` = `[(3, 50), (-1, 0), (-1, 0)]`，
`-1` 是"不使用该资源"的占位。资源 ID：0 Food / 1 Wood / 2 Stone / 3 Gold（与本文库 07 卷的属性表一致）。

### 1.6 克隆文明规则（写数据模组必看）

`d.civs` 是**每个文明一份完整副本**（63 个），`civs[0].units` 就有 2750 条。
改一个单位必须遍历所有文明改，否则只有第一个文明生效：

```python
for civ in d.civs:
    civ.units[83].hit_points = 50
```

这也是 genieutils-py README 里 `for civ in data.civs: civ.units[434].bird.tasks.pop()` 的原因。
（434 = 国王 KINGX，`bird` 是驻守相关子结构。）

## 2 AoE2ScenarioParser —— scenario 管线，但版本必须锁

### 2.1 版本坑（比 dat 那个更狠）

`pip install AoE2ScenarioParser` 在当前 Python 3.14 上默认解析到 **0.8.0**，而 0.8.0 的 effect API 是坏的：

```python
t.new_effect.display_instructions('hello')     # TypeError: Expected int, found: <class 'str'>
t.new_effect.send_chat('hello', player_list=[1,2])
# TypeError: send_chat() got an unexpected keyword argument 'player_list'
```

0.8.0 里 `display_instructions` 的签名是 `(object_list_unit_id, source_player, string_id, display_time, ...)`，
字符串要走 `string_id`；传 str 会被当成 unit id 做类型检查，然后炸在 `int_to_bytes`。

**必须显式装 0.9.9**：

```bash
pip install -U "AoE2ScenarioParser==0.9.9" -i https://mirrors.aliyun.com/pypi/simple
```

### 2.2 0.9.9 的正确写法

```python
from AoE2ScenarioParser.scenarios.aoe2_de_scenario import AoE2DEScenario

sc = AoE2DEScenario.from_default()
print(sc.scenario_version, sc.game_version)      # 属性在 0.9.9 上可用

t = sc.trigger_manager.add_trigger('test', description='d')
t.new_condition.timer(10)
t.new_effect.display_instructions(message='hello', display_time=5)   # 注意是 message=
sc.write_to_file('_probe/_tmp/dattest/v99.aoe2scenario')

sc2 = AoE2DEScenario.from_file('_probe/_tmp/dattest/v99.aoe2scenario')
len(sc2.trigger_manager.triggers)          # 1
sc2.trigger_manager.triggers[0].name        # 'test'
len(sc2.player_manager.players)             # 9
```

实测产物 716 B，重开条件/效果各 1 条，全部正确。

签名（0.9.9 实测）：

```
display_instructions(object_list_unit_id=None, source_player=None, string_id=None,
                     display_time=None, instruction_panel_position=None, play_sound=None,
                     message=None, sound_name=None, use_tag_color_for_icon=None)
send_chat(source_player=None, string_id=None, message=None, sound_name=None)
timer(timer=None, inverted=None)
```

**没有 `player_list=` 这个参数**，网上大量教程写 `player_list=[1,2]` 是旧版/别的库的记忆。

### 2.3 真实文件实测

本机 `~/Games/Age of Empires 2 DE/76561198406248391/resources/_common/scenario/` 下的真文件：

| 文件 | 版本 | 触发器 | 玩家 | 耗时 |
|---|---|---|---|---|
| `7V1变态山谷-炮塔盛宴-变态难.aoe2scenario` | **1.54** | **704** | 9 | 3.0 s |
| `The Siege.aoe2scenario` | **1.53** | 89 | 9 | 2.4 s |

704 个触发器的中文场景 3 秒读完，说明解析器不是玩具。
`sc.scenario_version` 报 `1.54` —— 当前 DE 的场景格式版本已经到 1.54，
而 0.8.0 时代的代码可能只认到 1.4x。

### 2.4 0.9.9 上没有的东西

```python
sc.scenario_data        # AttributeError（0.8.0 时代有这个属性名）
```

0.9.9 换成 `sc.structure` / `sc.sections` / `sc._scenario_data`。
要拿 header 里的游戏版本用 `sc.game_version`，不要去找 `.scenario_data.header.game_version`。

可用属性（实测 `dir`）：`LATEST_VERSION, actions, commit, from_default, from_file, game_version,
get_scenario, igenerator, map_manager, message_manager, name, new, on_write, option_manager,
player_manager, remove_store_reference, scenario_version, scenario_version_tuple, sections,
source_location, structure, trigger_manager, unit_manager, uuid, variant, write_error_file,
write_to_file, xs_manager`

## 3 录像管线：mgz 已死，aoe2rec 半活

### 3.1 mgz 1.8.51 —— 对 2026 年的录像 0 成功

```python
from mgz.summary import Summary
with open(f, 'rb') as fh:
    Summary(fh).get_json()
```

对 **8 个不同** `v101.103.54800.0` 录像全部失败，同一个错：

```
could not fast parse; falling back: could not parse:
construct.core.ConstError: expected b'`\n' but parsed b'\x00j'
    (parsing) -> de -> de -> players -> ai_type
construct.core.RangeError: expected 8 to 8, found 1
    (parsing) -> de -> de -> players
RuntimeError: invalid mgz file: expected 8 to 8, found 1
```

原因在源码里就能看出来 —— `mgz/util.py` 的版本表只到：

```
VER 9.3 / 9.4 / 9.8 / 9.9 / 9.A / 9.B-9.D / 9.E-9.F / MCP 9.F
```

而当前 DE 的录像头 `save_version` 已经越过这段（dat 侧已是 `VER 8.9` 一代的格式）。`de/player` 结构多/少了字段，
`ai_type` 的 `Const(b"\x60\x0A")` 对不上，后面全崩。

另外两个 API 变化（照 README 写会直接 `AttributeError`）：

```python
mgz.fast.header          # AttributeError —— 1.8.51 的 mgz.fast 只导出
                         # action/parse_action/postgame/Operation/Action/Age/MAX_PLAYERS...
mgz.get_version(fh)      # TypeError: missing 2 required positional arguments: 'save_version', 'log_version'
```

**结论：mgz 只适合读老 HD/AoC 录像。** 想读 DE 新录像别在它身上花时间。

### 3.2 aoe2rec-py 0.1.24 —— 能跑，但要容错

API（不是 README 里那个 `<TODO>` 的写法）：

```python
from aoe2rec_py.summary import parse_rec
r = parse_rec(open(f, 'rb').read())      # 传 bytes，不是文件对象
r.keys()                                  # ['chapters']
```

返回结构：`chapters[] → operations[]`，每个 operation 是单键 tagged union：

```json
{"Pregame": {"checksum_interval": 500, "multiplayer": true, "rec_owner": 14,
             "reveal_map": false, "use_sequence_numbers": false,
             "number_of_chapters": 0, "aok_or_de": false}}
{"Sync": {"time_increment": 124, "next": 3, "checksum": null}}
{"Viewlock": {"x": 19.0, "y": 76.0, "player_id": 2}}
{"Chat": {...}}
{"PostGame": {...}}
```

解析动作指令（建/走/攻）走 `operations` 里的 action 项，`ops=172871` 那种量级就是整局的操作流。

**成功率实测（14 个样本，跨大小）**：

| 文件 | 字节 | 结果 |
|---|---|---|
| rec.aoe2record | 1,217,795 | FAIL（rc=1） |
| …1010 231325 | 1,447,574 | FAIL |
| …1019 222335 | 1,891,714 | **OK** chapters=1 ops=811 |
| …1011 233739 | 1,925,875 | **OK** ops=1016 |
| …1009 233655 | 1,959,662 | **OK** ops=49 |
| …1009 232650 | 1,963,045 | FAIL |
| …1011 212430 | 4,021,589 | FAIL |
| …1013 205955 | 4,042,868 | FAIL |
| …1019 222735 | 4,195,704 | FAIL |
| …1007 194910 | 4,249,510 | **OK** ops=172871 |
| SP Replay …1003 | 34,455,833 | FAIL |
| MP …1017 220004 | 36,233,228 | FAIL |
| SP Replay …1003 202732 | 39,149,609 | FAIL |
| MP …1006 000108 | 62,308,326 | FAIL |

**4 / 14 = 29%**。失败有两种：

1. `panicked at crates\aoe2rec-py\src\lib.rs:14:62: called Result::unwrap() on an Err value`
   —— Rust 侧 panic，**会直接把整个 Python 进程带崩**（`rc=1`，无 Python traceback），必须放进子进程跑。
2. `bad magic at 0x<offset>: <n>` while parsing `operations` —— 中途遇到不认识的 op 码，`lib.rs:79`。

所以工程上的用法是：

```python
import subprocess, json, sys
p = subprocess.run([sys.executable, worker, path], capture_output=True, timeout=120)
if p.returncode != 0 or not p.stdout.strip():
    return None          # 这条录像放弃，换下一条
```

大小和成功率**没有**相关性（4.2 MB 成功，1.2 MB 失败），和版本/对局里用了什么也看不出规律 ——
按"能解析就解析，不能就算了"处理。

### 3.3 为什么坚持要 Rust/WASM 版

`aoe2rec-py` 的 `aoe2rec_py.cp314-win_amd64.pyd` 是 **cp314** 轮子，Python 3.14 上直接可用。
同一仓库还出 `aoe2rec`（Rust）与 WASM 版，`aoe2rec-py` 只是薄壳。
介意 panic 崩进程的话，用 Rust 库自己写容错解析器，或把 WASM 版放进 Node。

## 4 三条管线的落地组合（给本工作区用）

### 4.1 数据模组（改单位/科技数值）

```python
from genieutils.datfile import DatFile

SRC = r'...\resources\_common\dat\empires2_x2_p1.dat'
d = DatFile.parse(SRC)                 # ~7 s

for civ in d.civs:                      # 63 份副本，必须全改
    u = civ.units[83]                   # 村民
    u.hit_points = 50
    u.type_50.displayed_melee_armour = 5   # 面板显示值也要改

d.save(r'_mods_out\my_mod\resources\_common\dat\empires2_x2_p1.dat')
```

配 `info.json`（本文库 09 卷：`{"Author","Description","Title"}`）+ 镜像目录结构 = 可直接加载的本地 mod。
**注意**：data mod 一次只能启用一个，战役不可用（论坛帖 61109 的结论），能改单个资源文件就别做 data mod。

### 4.2 场景模组

```python
from AoE2ScenarioParser.scenarios.aoe2_de_scenario import AoE2DEScenario
sc = AoE2DEScenario.from_file('in.aoe2scenario')     # 704 触发器 3 s
tm = sc.trigger_manager
t = tm.add_trigger('my_trigger')
t.new_condition.timer(30)
t.new_effect.send_chat(message='30 秒了')
sc.write_to_file('out.aoe2scenario')
```

### 4.3 录像分析（做统计/复盘）

```python
from aoe2rec_py.summary import parse_rec
r = parse_rec(open(path,'rb').read())
ops = [op for ch in r['chapters'] for op in (ch.get('operations') or [])]
chats = [o['Chat'] for o in ops if 'Chat' in o]
```

要 header 里的玩家/文明/地图，改走别的路：
- `mgz` 读不了新录像；
- 最省事的办法是**读文件名 + 用 aoe2recs/其他站的已有解析**；
- 或者自己按 DE header 格式解（前 4 字节是长度类字段，之后是 zlib 压缩的 header，`aoe2rec` 的 Rust 源码是最全的参考）。
