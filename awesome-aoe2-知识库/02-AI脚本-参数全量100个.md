来源：<https://airef.github.io/parameters/parameters-details.html>（数据仍来自 `js/commands.js`）。

每个参数给出：UP 名（UserPatch 用法）、ES 名（游戏内官方文档用法）、版本、取值域 `range`、

## `ActionId`
*版本 UP · range `-1, 600 to 699.`*

**The current action(s) of an object.**

The current action(s) of an object. Sometimes an object can have more than one current action. It's also often wise to check an object's [OrderId](/parameters/parameters-details.html#OrderId) since orders last longer.

**取值表（24 项）**

| 值 | 说明 |
|---|---|
| `-1` | Use -1 to ignore the ActionId of the object. |
| `actionid-attack` | The object is attacking. |
| `actionid-defend` | The unit is defending. According to scripter64, this is hard to detect, because it quickly changes to other actions like actionid-move. |
| `actionid-build` | The villager or fishing ship is building, including farmers reseeding farms. |
| `actionid-heal` | The monk or missionary is healing. |
| `actionid-convert` | The monk or missionary is converting |
| `actionid-explore` | A unit is exploring. |
| `actionid-stop` | A unit is stopping its action. |
| `actionid-runaway` | Unknown? Could be non-combat units trying to get away from soldiers attacking them. |
| `actionid-retreat` | Unknown. Probably either retreating during a [up-retreat-now](/commands/commands-details.html#up-retreat-now) or [up-retreat-to](/commands/commands-details.html#up-retreat-to) command, or retreating because of minimum range or [ability-to-maintain-distance](/strategic-numbers/sn-details.html#ability-to-maintain-distance). |
| `actionid-gather` | Foragers, farmers, fishermen, gold miners, or stone miners gathering resources. Doesn't include lumberjacks or shepherds. |
| `actionid-move` | A unit that is moving. |
| `actionid-patrol` | A unit that is patrolling. |
| `actionid-follow` | A unit that is following. |
| `actionid-hunt` | A villager that is hunting animals, attacking wolves, herding livestock, or villagers gathering wood. |
| `actionid-transport` | A transport ship that is transporting units. Might also include transport ships that are on their way to picking up units. |
| `actionid-trade` | A trade unit that is trading. |
| `actionid-evade` | Could be units dodging missiles because of [ability-to-dodge-missiles](/strategic-numbers/sn-details.html#ability-to-dodge-missiles). |
| `actionid-enter` | A unit that is garrisoning inside a building, ram, or a transport ship. It may also include objects that are currently garrisoned. |
| `actionid-repair` | A villager that is repairing a building. |
| `actionid-train` | A building that is training a unit. |
| `actionid-research` | A building that is researching a technology. |
| `actionid-unload` | A transport ship that is unloading units. |
| `actionid-relic` | A monk trying to pick up a relic. |

相关参数：`GroupType`, `IdleType`, `ObjectData`, `OrderId`, `DUCAction`

## `AttackStance`
*版本 UP · range `-1 to 3 (-1 is invalid for [up-set-attack-stance](/commands/commands-details.html#up-set-attack-stance)).`*

**Controls the attack stance of military units.**

**取值表（5 项）**

| 值 | 说明 |
|---|---|
| `-1` | Do not set a new attack stance. |
| `stance-aggressive` | Aggressive Stance. Soldiers will attack all enemy objects in line of sight and chase them. |
| `stance-defensive` | Defensive Stance. Soldiers will attack most enemy objects in line of sight, but they will return to their original location if the enemy objects leave the area. |
| `stance-stand-ground` | Stand Ground Stance. Soldiers will only attack enemy objects if they can attack the unit from their current location. |
| `stance-no-attack` | No Attack Stance. Soldiers will only attack if ordered to target an object through DUC. |

相关参数：`Formation`

## `AttrId`
*版本 DE · range `a valid attribute from the list below.`*

**The id of an attribute to modify, such as attribute-hp.**

The id of an attribute to modify, such as attribute-hp. Since the [fe-cc-effect-amount](/commands/commands-details.html#fe-cc-effect-amount) and [fe-cc-effect-percent](/commands/commands-details.html#fe-cc-effect-percent) are similar to researching a custom technology for free, you can think of the AttrId as specifying what the technology will change or modify.

Please note that all of the attribute descriptions below are my (Leif Ericson's) educated guess, and I have done no testing on these attributes (yet).

**取值表（46 项）**

| 值 | 说明 |
|---|---|
| `attribute-hp` | The object's hit points. |
| `attribute-los` | The object's line of sight. |
| `attribute-obj-max` | Unknown. |
| `attribute-radius-x` | Unknown. Possibly the radius of the object's size in the x direction. |
| `attribute-radius-y` | Unknown. Possibly the radius of the object's size in the y direction. |
| `attribute-speed` | The object's speed. Probably multiplied by 100, but this is untested. |
| `attribute-turn-speed` | The time it takes the object to turn from one rotation/facing direction to the next. Most objects' turn speed is zero, but this is observable for ships and trebuchets. |
| `attribute-armor` | The object's armor. Unknown whether this is melee armor, pierce armor, or both, but it's likely just melee armor. It seems like there isn't a way to choose which armor type to modify, or there is a complex formula that allows you to specify the armor type and amount in a single value. |
| `attribute-weapon` | Unknown. Probably the object's attack. It's possible there is a complex formula that allows you to specify the type of attack/attack bonus and the amount in a single value. |
| `attribute-speed-of-attack` | The object's attack speed. Unknown whether this is given in seconds or milliseconds, but probably the latter. |
| `attribute-hit-chance` | Unknown. Probably the object's accuracy. Likely multiplied by 100. |
| `attribute-weapon-range` | The object's range. |
| `attribute-work-rate` | The object's work rate. This attribute is primarily relevant for buildings, which determines the speed that units and techs are trained and researched. |
| `attribute-carry-capacity` | The amount the object can carry. This affects the resource capacity villagers can carry and also the amount of resources that Gaia/player owned resources can hold. |
| `attribute-base-armor` | Similar to attribute-armor. Untested, but this likely affects the original armor amount, so it wouldn't display as + or - like it would for blacksmith armor upgrades. |
| `attribute-missile-id` | The ID of the object's projectile. See the Proj. ID in the [Objects Table](https://airef.github.io/tables/objects.html) to get the projectile IDs of each unit. |
| `attribute-building-facet` | Unknown. Likely the rotation the building faces, though most buildings only have one direction anyway. |
| `attribute-defensive-terrain` | Unknown. Could be the same as Terrain Defense Bonus from Advanced Genie Editor. |
| `attribute-targetting-type` | Unknown. |
| `attribute-minimum-weapon-range` | The object's minimum range. |
| `attribute-attribute-amount-held` | Unknown. The attribute-attribute in the attribute name isn't a typo. ;) |
| `attribute-area-effect` | Likely the object's blast radius. |
| `attribute-search-radius` | The object's search radius. This is often equal to LOS, and it determines the radius where the object will respond to enemy units. |
| `attribute-hidden-damage-resist` | Unknown. Could be the same as the Bonus Damage Resist field from Advanced Genie Editor. |
| `attribute-icon-id` | The ID of the object's icon. |
| `attribute-fire-missile-at-frame` | Likely the frame delay, the number of graphical frames to must be displayed from the attack animation before the projectile will fire. |
| `attribute-area-effect-level.` | Likely the object's blast attack level. The blast damage for objects with level 3 or higher only damage the targeted object. The blast damage for objects with level 2 will damage nearby objects that are within the blast radius of the attack. The blast damage for objects with level 1 can damage trees. The blast damage for objects with level 0 can damage all resources. Note: many buildings and cavalry units have blast level 0, so it is wise to check if the blast radius is > 0 before checking the blast level. |

| `attribute-shown-attack` | The object's shown attack. A + or - value will be displayed in the interface if the actual attack is higher or lower than the shown attack, respectively. |
| `attribute-shown-range` | The object's shown range. A + or - value will be displayed in the interface if the actual range is higher or lower than the shown attack, respectively. |
| `attribute-shown-melee-armor` | The object's shown melee armor. A + or - value will be displayed in the interface if the actual melee armor is higher or lower than the shown attack, respectively. Uncertain if shown pierce armor can be affected with this attribute. |
| `attribute-name-id` | Likely the language ID location of the object's name. |
| `attribute-description-id` | Likely the language ID location of the object's description. |
| `attribute-terrain-restriction` | The terrain the object can travel or be placed on. Likely the same as the Terrain Table field in Advanced Genie Editor. |
| `attribute-death-spawn-obj` | The ID of a new object that is spawned when an object dies. This is usually the unit's corpse or ruins, but it is used by the Konnik to spawn a dismounted Konnik when the mounted Konnik dies. |
| `attribute-hotkey-id` | Likely the language ID location of the letter for the object's default hotkey. |
| `attribute-resource-cost` | Likely let's you change the [ResourceType](/parameters/parameters-details.html#ResourceType) cost for a resource besides food, wood, gold, or stone. |
| `attribute-creation-time` | The amount of time to create the object, in seconds. |
| `attribute-garrison-arrows` | Likely either the extra number of projectiles the object will fire or the max number of arrows the object can fire when fully garrisoned. Not sure how this differs from attribute-max-dup-missiles. |

| `attribute-regenration-rate` | Note the [incorrect] spelling. The speed the object will heal at. Likely multiplied by 100 or 1000 (not sure which, sorry). |

*版本 UP · range `-1 to 10.`*

**An object's command ID.**

An object's command ID. The command ID (or interface type) determines the available actions for the object or which actions display in the bottom left corner when the object is selected. To determine an objects command ID, look up the object's Interface Type in the Advanced Genie Editor.

| `cmdid-civilian-building` | Non-military buildings command ID. |
| `cmdid-villager` | Villager command ID. |
| `cmdid-military` | Military command ID. Used by military soldiers, siege weapons, and warships. |
| `cmdid-trade` | Trade units command ID. Includes both Trade Carts and Trade Cogs. |
| `cmdid-monk` | Monk and Missionary command ID. |

## `ColorId`
*版本 UP · range `1 to 8.`*

**A color number ID.**

A color number ID. These colors correspond with the player number color where 1 = Blue, 2 = Red, etc. Each color will always return the same color ID, even if it doesn't match the player number. If player 4 is Blue, player 4's ColorId will still be 1.

## `DUCAction`
*版本 UP · range `a valid DUCAction from the list below.`*

**The action to perform with the selected units.**

The action to perform with the selected units. Some DUC Actions cannot be taken with [up-target-objects](/commands/commands-details.html#up-target-objects).

**取值表（22 项）**

| 值 | 说明 |
|---|---|
| `action-default` | Equivalent of a right-click for all objects in the local list on the point or target object(s). For [up-target-point](/commands/commands-details.html#up-target-point) this is the same as action-move. |
| `action-move` | Units in the local list will move to the point or the location of the target object(s). |
| `action-patrol` | Units in the local list will patrol to the point or the location of the target object(s). |
| `action-guard` | Units in the local list will guard the target object(s). For [up-target-point](/commands/commands-details.html#up-target-point) this is the same as action-move. |
| `action-follow` | Units in the local list will follow the target object(s). For [up-target-point](/commands/commands-details.html#up-target-point) this is the same as action-move. |
| `action-stop` | Objects in the local list will stop their current action. |
| `action-ground` | Units in the local list will attack ground at the point or against the target object(s). |
| `action-garrison` | Units in the local list will garrison inside the target object(s). For [up-target-point](/commands/commands-details.html#up-target-point) this is the same as action-move. |
| `action-delete` | Deletable objects in the local list will be deleted. |
| `action-unload` | Buildings in the local list will ungarrison to the target point. Siege (class 913) in the local list will eject in place. Transport ships in the local list will unload at the target point. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-train` | Buildings in the local list will train units. To train units, use this syntax: ([up-target-point](/commands/commands-details.html#up-target-point) [EscrowGoalId](/parameters/parameters-details.html#EscrowGoalId) action-train [typeOp](/parameters/parameters-details.html#typeOp) [TypeId](/parameters/parameters-details.html#TypeId)). Example: (up-target-point 0 action-train c: spearman-line). For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-gather` | Buildings in the local list will set their gather point at the given point or at the location of the object(s) in the remote list or the target object. Some buildings, like towers, cannot set gather points onto units or gaia animals, and using action-gather with [up-target-objects](/commands/commands-details.html#up-target-objects) will simply set the gather point to the location of those objects. To reset a gather point, use (up-target-point g-point-x action-gather -1 -1), where the coordinates of g-point-x are (-1, -1). [sn-target-point-adjustment](/strategic-numbers/sn-details.html#sn-target-point-adjustment) must be set to 0 to reset the gather point. |
| `action-lock` | Gates in the local list will toggle their locked state. If they are locked, they will unlock. If they are unlocked, they will lock. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-work` | Buildings in the local list will send garrisoned villagers back to work. Same as clicking the Send Back to Work button. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-ungarrison` | Units in the local list will be ungarrisoned from the building they are garrisoned inside. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-drop-relic` | Monastery units in the local list will drop any relics they are carrying. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-pack` | Trebuchets in the local list will pack. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-unpack` | Trebuchets in the local list will unpack. For [up-target-objects](/commands/commands-details.html#up-target-objects) this is the same as action-none. |
| `action-none` | The current actions of the objects in the local list will not change. |
| `action-attack-move` | Must be defined with a defconst. Only available in DE. Units in the local list will attack move to the point or the location of the target object(s). |

## `ObjectList`
*版本 UP · range `0 or 1.`*

**Either list-active or list-inactive.**

Specifies whether the filter should apply to objects in the active list or the inactive list.

Here's some background info from scripter64 in response to a question on why some custom flags in a mod weren't being animated:

Custom building flags can't be animated due to the performance overhead of updating them. There can be many houses and wall segments (each one counts as a separate "building") on a map each game, so ES moved these objects into a separate [inactive] list that does not update per-turn to avoid excessive computational overhead. When attacked, they are moved into the main per-turn update list in order to animate their fire if necessary. Gates are always in the main list.

The current flag fix only enables the palisade wall ends to animate by moving those specific objects into the main object list that can update per-turn for redrawing and animation. It would probably be bad for the general performance of the game if we were to undo the ES optimization entirely and allow all objects into the per-turn update list.

**取值表（2 项）**

| 值 | 说明 |
|---|---|
| `list-active` | Contains most objects, especially live objects. |
| `list-inactive` | Contains objects that are removed from the active list for performance optimization. Examples are fish, dead animals carrying food, and maybe house foundations. Chopped trees are usually list-active. |
