# 逐字段编辑器：设计取舍与实测记录

`README.md` 的「逐字段编辑器」一节只放表；这一份是表后面的为什么。
每一条都对应一次实测或一次被推翻的假设，改这一页之前值得先读一遍。

---

**不只是改，还能多一条、少一条。** AGE3 的表格编辑器只能动现有的格子：它没有「新增」，
因为 `.dat` 里一条记录的位置由别的地方的指针决定，多一条就要动指针数组、动计数、动后面
所有偏移。这里做了这件事，代价是几十毫秒而不是整份重写：复制一条单位记录
**0.17 秒**（文件 +111,391 字节 = 记录本体 2,387 + 27,251 个新指针槽 × 4），
追加一条科技 **0.045 秒**（计数 +1 只动 2 字节），删回去**逐字节回到原始文件**。
增删之后整份模型要跟着挪位，因为所有偏移都变了——但**不是重读**：一次编辑是一组
`(at, cut, add)`，知道哪儿插了几个字节，它后面的偏移就都平移那么多（136,861 条记录的
偏移一起平移 **0.28 秒**），只有被改的那个文明重走一遍（**0.07 秒**）。**1.2 秒**，
撤同样 1.0 秒；而且挪完之后要先自证（首尾是否相接、末文明是否正落在技术段起点），
证不出来就退回重读那条老路——快路出错的方式是变慢，不是变错。删除一个还被别处引用的记录不会静默执行：先告诉你
「还被 48 条效果命令和 63 份文明记录引用」，要再确认一次才动。

**而且不是一条一条地加。** 要一千条就填一千，一次写完、一次撤回：1,000 条 = 4 步计划的
字节工作 **0.037 秒**，10,000 条 **0.047 秒**（时间花在随后那次挪位，不在条数上）。
列表默认按编号排，复制出来的记录会排在最后一页，所以工具栏有个「最新的在前」——
它是同一份列表从另一头读，号码最大的那页先出现，不用翻到第 5 页去找自己刚建的东西。
选择也不只一种：`Ctrl+A` 选这一页、`Shift` 连选、`Ctrl+C` / `Ctrl+V` 把选中的复制成新记录、
`Delete` 删除、`Esc` 取消、方向键走列表、`Shift+方向键` 扩选、`Ctrl+Z` / `Ctrl+Y` 撤回重做。
在输入框里这些键不接管：那里的 `Ctrl+A` 是选文字。

**新增也可以不从别人身上抄。** 工具栏的「新增空白」做出来的是一条**从零写**的记录
（类型 70，476 字节）：名字 `NEWUNIT<编号>`、图形与图标与造价与训练点全是 0，
`train_locations` 是空表——它在这个文明里存在，但还没有任何建筑能生产它，
等着你用右边的字段一格一格填。这件事在 2026-11-06 之前做不到，因为一条记录的尾巴
由类型决定（10/15 无尾、30 DeadFish、40 Bird、50 Type50、60 Projectile、70 Creatable、
80 Building），每段还有十个版本守卫，从零写等于每个字段猜一次，猜错的表现不是
「这条看着不对」，是它后面两万条记录全变垃圾。现在的做法是猜一次然后**自证**：
写完立刻用将来读它的那个函数（`walk_unit`）读一遍，要求走到最后一个字节正好用完；
18 个游戏版本各走一遍（长度 476→408 不等），全部闭合才写进文件。

**数字之外还能看。** 改了生命值或换了贴图之后，单位标题下面有「看动画」：点开就是一整段
动画横排铺在面板里（村民走路 20 帧是一条 479×38 的图，13,929 字节），帧数与朝向数从
HTTP 响应头回来，因为 body 就是一张 PNG。一段动画能画多少帧由**文件**决定而不是记录声明 ——
全库有 16 个 `.sld` 被记录用互相矛盾的网格说成两种帧数，这里取能复现文件自身帧数的那一条。

**为什么单开「效果」这一页。** 一条科技并不拥有自己的效果，它只有一个 `EffectID`
指针：实测 1,510 条科技指向 1,500 条效果记录里的 1,014 条，于是**剩下 486 条记录
（2,795 个数字）不属于任何科技** —— 从科技那边永远点不进去，AGE3 里也只有翻原始
结构才能看到。这一页把它们全部列出来。

几条设计上的取舍：

- **改一份还是改 63 份**。单位记录按文明各存一份（实测单位 74 的 434 个字段里有 424
  个在 63 个文明中完全相同），所以写范围默认「全部 63 个文明」—— 只写一份的话，游戏
  里那 62 个文明看到的还是旧值，而工具已经报了成功。
- **先看看 → 记下这个改动 → 保存全部改动**。前两步只动内存，第三步才写一次 93 MB。
  在值框里直接按 Enter 就等于「记下这个改动」。
- **改错了能撤回**。页头「已改 N 项」旁边有「撤回」「重做」，Ctrl+Z / Ctrl+Y 也行。
  一步是一个手势，不是一次字节写入：「所有文明血量改成 100」写 63 份记录，撤回按一次
  就全回去。存的是字节对，所以撤回之后内存缓冲区和游戏原文件逐字节相同。撤回后再改
  一个字段，那条「未来」就作废（和所有编辑器一样）；「放弃」和「保存」都会清空历史。
  焦点在输入框里时 Ctrl+Z 不拦，让浏览器的文本撤销赢。
- **指针列显示名字，不只是数字**。`EffectID = 22` 旁边写出「织布机」，`SlpID = 140`
  旁边写出记录自己的名字 —— AGE3 只给整数。
- **`-1` 和 `0` 逐行解释**。同一个 `-1` 在图标编号里是「没有图」，在指向类字段里是
  「不指向任何东西」，所以每行按自己的 hint 标注，表格上方另有一张总说明。
- **图形、音效、效果不按文明分**：同一个图形所有文明共用一条记录，所以那三个页签没有文明下拉。
- 图形表 20,883 行、每次翻 400 行，但只列**有名字的**记录：3,520 个图形和 491 个音效
  没有名字（没有东西指向它们），列出来只是噪声。计数器数的是你翻得到的那些行，旁边
  另写「表共 N 条」—— 两个数存在是对的，只印一个才是 bug。
- 效果表只列**带命令的**记录：1,500 条里有 184 条是空槽，它们合计 0 条命令；反过来
  302 条有命令却没有名字的必须列出，那正是这一页存在的理由。所以判据是「这条记录说
  不话」，不是「它有没有名字」。
- 效果命令的五个槽里**只有数值可改**。类型、参数1/2/3 决定这个数字是什么意思（改成另
  一个类型，同一个 15 就变成完全不同的效果），所以它们逐行标「只读」并说明为什么要换
  效果得去科技那边新建一条命令。
- 页面一次请求取整页图标（`/api/icons`）。原先每行一个请求，400 行要 3.6 秒才画完，
  截在那几秒里的图看起来像「图标坏了」。
- **模组页两个看法**：页头「列表 / 图 + 简介」两个 chip 切的是**同一个** `#mods` 容器，行还是那一批行。卡片是 288px 一格：96×54 缩略图、作者写的简介（三行）、作者名；没有图写「没有缩略图」而不是画一个空框（空框会被读成「还在加载」）。这台机器上 23 个模组里 17 个带 `thumbnail.png`/`.jpg`、6 个没有，`info.json` 里 **一个** 缩略图键都没有 —— 图是扫文件夹扫出来的。开关、上下箭头、「放进回收站」在两种模式下都在，切回去就还是原来那一列。
- **换图标**：记录里那个图标编号只是一个数，图在别处——贴图文件、`materials.json` 的
  两条、`icons.json` 的键。所以「换图标」是一个动作写四处，不是改一个数。记录上方点开
  「换图标」挑一张图，服务端把槽位与材质名念出来再让你按。
  **默认「原地换」**：记录本来就指着某个图标槽，那就把那个槽的材质换掉，`.dat` 一个
  字节都不动 —— 所以模组是**一个文件夹，启用一次**。代价写在预览里：槽号是共享的
  （槽 8 上还挂着另外两个单位），原地换会把它们一起换掉，预览会把它们列出来。
  只有「取消原地换」时才另开一个新槽、改记录里的编号，那要写 `.dat`，而**带 `.dat` 的
  构建会拆成两个文件夹**（同一个文件夹同时带 `.dat` 和 `widgetui/` 时引擎忽略界面层）
  —— 两个都要启用，少一个就是空框。
- **启动时会先弹一次防伪声明。** 模态窗、六条、左下「本周不再提示」、右下「我知道了」。面板是浅色的，和这个窗口里每一面一样：拿来的只是那个例子的版式，不是它的配色。
  那六句话不在窗口里写第二遍：窗口打开时从「关于」页的「防伪声明」那一节抄过来，
  页面上这句话只出现一次（多一份就多一份会过期的）。× 与 Esc 是「现在不看」（下次启动还来），
  勾了框才是「这七天不看」（存一个时间戳，滚动七天，不是自然周）。关于页里那一节末尾有
  「再看一次启动时那个窗口」，改完声明想复核不用等下周。
- **启动那扇窗右边的那半张，放着一张图。** 窗里六条声明被 `--measure`（约 62 个字）
  限在 509px，这是为读起来舒服定的，不该放宽；面板比这宽，于是右边一直空着。图就放在
  那块空处：和六条并排、靠右、宽 240，窄窗口下自己掉到六条下面。面板因此加宽到 900px
  （509 + 16 + 240 放得下）。它是一张真文件（`aoe2mod/ui/static/art/preview-girl.jpg`，
  从 `/static/...` 按 `image/jpeg` 送出），标记里的 `width` / `height` 与文件自己的尺寸
  逐字相等，`alt` 写着一句人话。玩家的原话是「我说的是图片放这个窗口这里」——第一版我
  把它放进了「关于」页，被要求还原了。
- **关于页九张卡按两栏排，因为单栏时每张卡右边空着一半。** 卡是 1056px 宽，卡里的段落被
  `--measure`（62 个字）限在 509px，右边 547px 一直是空的——玩家说「你右边空那么多空白干什么」。
  两栏之后整页从 2482px 收到 1327px。用的是 `column-count` 而不是两列 grid：grid 按行对齐，
  矮的那张卡底下会留 252px 的空，洞只是从右边搬到下边；按栏平衡之后卡与卡之间全是那个 16px
  的间距。760px 以下回一栏。**第一版把断点写在 1100px，1000px 时是一张 968 宽的卡配 509 宽的
  字，右边空 459——那个断点自己在制造同一个问题。**
- **「关于」页说清这个工具是什么，也说不做什么。** 左侧第七个页签：署名 RemonBo、爱发电 /
  B 站 / GitHub 三个地址，每个地址一行两个字：**复制链接**、**浏览器打开**。地址本身印成纯文本
  （**不是可点的链接**：桌面包没有地址栏也没有返回键，一条外链会把工坊换成回不来的网页）；
  「浏览器打开」是把地址交给服务端，由系统默认浏览器去开，工坊这扇窗留着。服务端只放行
  `http` / `https`，其余整类拒绝并说出被拒的是什么（Windows 上 `webbrowser` 走 `os.startfile`，
  `file:` 会启动本地的可执行文件）。下面依次是版权归属、可以做什么、不可以做什么（不许卖、
  不许改署名再发、不含破解、不分发素材、不拿它联机作弊）、免责。版本卡分三行：第一行是这个工具自己的版本（`ver 1.0`，来自
  `aoe2mod/appversion.py` 一处常量，服务端放进 `/api/meta` 的 `app_version`），第二行是这一次运行真读到
  的数据格式与文明数，第三行是 GitHub 上有没有更新的版本（自己读仓库里的 `appversion.py`，
  不和第二行混用——那一个是本地文件说的，这一个是网上的文件说的）。屏幕上同时有三个「版本」（这一份软件 / 游戏 build / `.dat` 的 FileVersion），
  混在一句话里任何一个都会被读成另一个。页面上不留任何写给我自己的解释。
- **命令面板一屏 15 格，引擎画两屏，所以能写到第 30 格**：第 0 格在文件里存着 27,838 条建造项（村民采集、城门形态），可 62 个文明的科技树里**一条都没有**，引擎从不画它。第 1..30 格是一屏一屏画的：写到第 15 格以后，游戏自己会在第 15 格和第 30 格画出那个红色箭头，点它翻到第二屏（这不是 `commandpanel.json` 里的控件，那个文件里只有 15 个 `CommandButton`，箭头是引擎按格号分组画的）。第 31 格以后引擎读得到但永远不画，所以写入在第 30 格停。这一页也因此有「面板页」两个按钮：一屏一屏看，不是把 30 格摊平。**第二屏是能写的地方，不是一个「有东西才存在」的地方**——它由引擎的屏数决定，不因为这一屏还空着就藏起来，所以第 16 格永远进得去、放得进东西。一格上写的「10 / 16 条」是「任何文明能造 10 条 / 文件里 16 条」，鼠标停上去能看是哪 16 条、各几个文明能造——兵营第一格那 16 条是 16 个文明各自的升级链叠在同一格，你这个文明只看到其中 5 条。每格左上角是游戏自己的图标。面板顶上那行还会说清**正在改哪份 .dat、游戏会不会读它**（装了改数据的模组时，本体那份写进去了也看不见）。改完不用跳到编辑器：这一页自己就有「已改 N 项 / 撤回 / 重做 / 保存全部改动」，和编辑器读的是同一条会话。
- **一格不止一条科技：这就是社区说的「伪翻页」，而且真的没有上限**：一个格子画一个按钮，但**同一个格号能挂任意多条科技**，每条可以反复研究、造价为 0 或负数，点一下就把一批单位的「训练地点」关掉、把下一批打开 —— 于是同一格的每一页都是一批别的兵。那辆「选文明的骡车」（建筑 5066）第 15 格就是这么干的：`Cycle 1`..`Cycle 5` 五条科技同一个格号，每条 29 条效果命令（14 条把 5000..5013 关掉 + 14 条把下一批打开 + 1 条改前置科技的时间），第 5 页打开的那批正是第 1 页关掉的那批，闭环。**一页只值几十字节**：81 字节的科技 + 18 + 11 × 命令数的效果记录；实测给第 15 格加第 6 页，文件只长 317 字节。所以「无上限」不是引擎没有上限，是这件事本来就很便宜。**这个功能就长在图标窗口里**：点一个空格子，条带照旧在下（写完了、窗口关掉，它还在那儿），而图标窗口同时打开，顶上一条「伪翻页：这一格还不是会翻页的按钮」+ 一个「在这一格建一个伪翻页按钮」（没有任何单位也行，**先建页再往里放**）。建好之后那条上多出一枚「第 1 页 · 空」的 chip：**点这枚 chip，同一个窗口就对准那一页**，之后每点一个图标都落进这一页，窗口不关，可以连着点好几个；点「放回整格」就回到往格子里放。窗口里还挂着「删掉第 N 页」和「再加一页（空的）」，按在页上时「建筑」「科技」两个页签是灰的（一页只装单位）。页里每个单位右上角的 × 把它拿掉。整页就是几个格子加一个 ×，没有编号要背，也没有输入框要填：**一步 1.5 秒以内、每一步一条撤销，撤销后文件逐字节回原**。窗口只有一个（和「放一个单位进这一格」是同一个），瞄准哪一页是窗口里那排 chip 干的，所以不存在第二套选择器。**代价要说在前面**：翻页就是改写「这些单位现在能在哪训练」，所以这座建筑正在生产的队列、正在研究的科技，会在翻页那一刻消失 —— 数据层没有东西能保住它。功能里做了两件事把它压到最小：研究时间写 **0 秒**（没有研究窗口可以被取消），以及每一页关掉的是「其它所有页打开过的单位」而不是「上一页打开的单位」（乱序点也只会有一批能训练）。屏幕上就写着这句话。新模块 `aoe2mod/dat/pseudopage.py`，路由 `GET /api/pseudo-pages` 与 `POST /api/pseudo-pages`。

  **这一页不等自己问，是服务端告诉它。** 早先每放一个图标，页面要整套重读一遍命令卡——两次请求，
  其中一次要走完 89 MB 的文明块——于是连点三个单位就是三次整屏重画，玩家报的是「这个页面依旧是
  不能实时更新的」。现在改了三件事：

  - 三个页动词（建页 / 删页 / 页里加单位删单位）**把它们改完之后的页列表自己带回来**（`page_list`，
    每页带 `on_list`，每个单位带名字），页面按答案重画条带、格子上的徽章和窗口顶上那排 chip，
    不再 re-read 卡片。一次点击从 1.5 秒变成一条往返。
  - `GET /api/live?since=N` 是一条**长轮询**：把手上已有的版本号交上去，服务端有别处改了就把这条
    请求叫醒，答同一套计数（已改 N 项 / 可撤回 / 可重做 / 字节数 / 版本号）。停在别的页签上的窗口
    也一样会变。撤回与重做也是变更，一样唤醒。
  - 一次变更是一串「拼接 + 重解析 + 改计数」，中间每一步都通知会让等在门口的屏幕读到**半步之后**
    的数（字节已经回去了、`undo` 还说 1）。所以写路径全程「握紧」：版本号继续涨，但没人被叫醒，
    直到这次请求自己的答案完整。钉子在 `_probe/test_live_panel.py`。
- **格子上那枚「N 页」从第一页就开始写，而且它数的是屏不是按钮**：同一个格号挂一串伪翻页科技时，
  格子左上角有一枚徽章写「N 页」，鼠标停上去能看这一格挂了几条、每条哪几个单位。这枚徽章原先要**两页**
  才出现，理由是「一页看起来跟没有页一样」——这话对卡片成立，对格子不成立：玩家点「在这一格建一个伪翻页
  按钮」的那一刻盯的就是格子，格子空白就等于没点上。现在一页即画。同一格的溢出行「还有 N 项科技」也曾经
  在有了页之后改口叫「还有 N 页」，把放不下的 8 个研究按钮说成 8 屏；现在它固定数按钮，屏幕数交给徽章。
- **模组前后顺序拖一下就换**：拿住任意一行（列表和「图 + 简介」两种视图都行）拖到别的位置，松手就写到 `mod-status.json` 的数组顺序里——那是引擎读的顺序，越靠上越先加载，两个模组改同一个东西时上面那个赢。一次拖动只写一次文件，不是十七次；落在原地不发请求，落在格子的下半算「放在它后面」（不然最后一行永远拖不到末尾）。服务器那条是 `POST /api/mod-move-to {name, position}`，位置是格子不是距离。
- **拖动在桌面版里也能用**：网页里 HTML5 拖放是好的，但玩家双击的那个 exe 里一行也拖不动——外壳要在资源管理器拖文件进来，装了 drop handler 就把 HTML5 的拖放整个收走了。所以模组行与命令面板格子都改成指针事件三段式（4px 阈值 + `elementFromPoint` 命中 + 松手时算落点）。同一个原因下顺手补了两件事：一个被切片补丁删掉的 `stored()`，和中文名的第二种编码（GBK）。
- **中文名有三种写法，三种都要认，而且认错了比不认更坏。** 出厂数据全是 ASCII；玩家的模组把中文写进
  `.dat` 的 byte string 时，有的写 UTF-8（那份 125 MB 的模组里 230/5,874 个科技名、4,473/136,861 个单位名
  是这样），有的写 GBK（`°¢×ÈÌØ¿Ë` 是「阿兹特克」、「¡¤¡¤[ÖÐÌï]¡¤¡¤」是「··[中田]··」）。
  解码只发生在屏幕这一侧，`parser.py`/`writer.py` 一个字节都不猜。GBK 的三条判据是：字节能编回自己、
  高位字节是偶数个、每个非 ASCII 字符落在汉字区**或者**在那张 13 个字符的装饰标点表里——最后这条是
  白名单不是放宽，因为把「有汉字就放行」当作修法会把 `Écossais` 印成「蒫ossais」。17 份 `.dat` 全量重扫：
  0 条单位名、0 条科技名仍是字节。
- **搜索框里打数字，就是找那个编号。** 命令面板写着「打名字或编号，比如 村民、83」，编辑器的框写着
  「按名字或编号过滤…」，而 `browse` 原先只比名字——你能看见记录旁边写着「编号 5073」，
  却没有任何办法用这个数字找到它（实测 `q=83` 答 0 条、`q=村民` 答 3 条）。现在数字先精确比 id
  （不是前缀：前缀会让 5073 和 50730 挤在一起，看着像搜错了名字），名字那一路照旧。

- **一份数据模组有多旧**：看版本头，不看「格式 54」。`格式 54` 是 FileVersion 的布局序号（7.1→36 … 8.9→54），14 份候选里唯一落后的是 `10 倍资源文明联盟3倍科技`：**VER 7.8，比本体早 11 个格式台阶**，46 个文明（本体 63）、13012 条图形（本体 21001）。量一份 0.17–0.35 秒（只读前 8 MB，不解析文明记录），结果按 `(mtime, size)` 缓存。结论只由版本头决定——计数是体积，不是年龄，`Pompeii` 与本体同格式、只留 18 个文明，不该被判旧。
- **改哪一份 `.dat` 一句话就说清，而且能换**：模组页顶部一块「改哪一个数据文件」，这台机器上 14 份（本体 1 + 模式 1 + 带 `.dat` 的模组 12）一行一个。每行写三件事：是什么（标签，不是路径）、什么时候会被游戏读、格式号。**「我在改哪一份」和「游戏读哪一份」是两个问题**——五个启用的数据模组抢，优先级最高的赢。这两个答案只写在列表上方那一句里（「优先级最高的是「X」。改别的份游戏看不到。」），正在改的那一行标「正在改」。每行曾经还挂一枚「游戏现在读的是它」的牌子，被要求去掉了（2026-11-07：「这个不需要，去掉吧」）——十五行各挂一枚标签，比一句话说清更费眼睛。格式 43（`VER 7.8`）是可改的，解析器认识 36..54；说它改不了是反方向的假警告。点「改这一份」会重建整个会话，并报出丢了几项没保存的改动。
- **一格有时代，而且一个格子要两个数**：时代不在 `.dat` 里，在 `resources/_common/dat/futuravailableunits.json` 的 `RequiredAge` 里。跟科技树的 `Age ID` 逐行对照（每个文明对自己那棵树）：2,794 行一致、7 行不一致，不一致时面板赢——勃艮第的 Cavalier 面板写 4、它自己的树写 3，引擎读面板。可面板是按（文明、建筑、节点）写的，所以同一个单位能有两个时代：主文件 272 个节点里有 13 个、两份文件合计 320 个里有 14 个，其中只有一个真平票。一格是一条升级链，所以一格给两个数——`age` 是最早那一代、`age_span` 是区间，跨时代的格子标成对比色。顶上「按时代」五个 chip 是**只淡不藏不重排**：格号就是游戏读的那个字节，重排就是画一张不存在的卡。选城堡时代时兵营有 3 格亮着（第 1、2、4 格），因为规则是包含而不是相等。空格子在过滤时也淡下去——十一格亮着的洞会让过滤器看起来像坏了。
- **拖动格子不再把字选中**：模组行有 `body.dragging-row` 兜着，格子没有；而选区在第一次 `pointermove` 就产生了，可能早于那个类被加上。格子自己写 `user-select: none`，按下时再清一次已有选区。
- **命令面板能改，不只是能看**：点一个格子可以改它的训练时间、把它从这张卡上拿掉；下面的搜索框把本文明的任何单位加进第一个空格。`button_id` 不是卡上的字段，是单位记录里一条 9 字节建造项的第五个字节，所以「加一项」是 +9 字节的 splice，后面所有偏移跟着挪（增量的，约 1 秒）。拖动能换格，一样可撤回。
